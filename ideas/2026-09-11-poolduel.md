# Poolduel: PostgreSQL Pooler Shootout (Architect Blueprint, Issue #302)

## Summary

Exhaustive, honest, publishable shootout of five PostgreSQL connection poolers
(pgagroal tip, PgBouncer 1.25.2, pgpool-II 4.7.2, Odyssey 1.5.1, pgcat v1.2.0)
plus a direct-PG control, driven by pgbench under `clients >> pool_size`
fan-in. The Researcher spec (committed under `poolduel/docs/`, Refs #302) is
normative for modes, matrix, grid, methodology, versions, configs, and the
harness contract. This blueprint turns that spec into a buildable system:
a Python harness with six pooler-blind adapters, a chunked CI workflow
(postformer pattern), and a static Pages report. Supavisor v2.9.13 stays
deferred per `docs/supavisor-deferral.md`; no Supavisor numbers, no zeros.

## Deliverables

- M1: Python harness + 6 adapters + M1 matrix runner (7 transaction cells
  plus control, pilot gate enforced) + raw JSON and medians artifacts +
  working `poolduel/repro.sh`. Refs #302.
- M2: session/statement/mode arms + I/O sweep axes (io_uring vs epoll,
  so_reuseport instances, workers, worker_threads) + extra workloads
  (select-only, simple-update, churn/prepared twins). Refs #302.
- M3: static Pages report at `/poolduel/index.html` (tables, deltas,
  N/A and inconclusive rendering, threats section) + full M1+M2 audit +
  one-command repro verified by Tester. Closes #302 (only on passing
  binding gates; negative results stay Refs).

## Why

Pooler choice is load-bearing infrastructure and vendor benchmarks are
home-team theater. Poolduel earns trust structurally: one shared
procedure, identical adapter treatment, equal cell budgets, best-vs-best
plus iso-region slices, non-overlapping-band gates, and adversary-grade
disclosure (verbatim configs, raw logs, seeds). The value is the ranking
inside a stated hardware envelope, not an absolute capacity claim.

## How It Works

1. Provision: pinned PG 17, fresh `pgbench -i -s 10`, `CHECKPOINT`,
   pooler under test started via its adapter from the verbatim baseline
   in `docs/configs/<pooler>.md` (every non-default cites upstream docs).
2. Pilot: M1-1 + M1-2, one repeat per arm, round-robin interleaved. All-tie
   (overlapping bands everywhere) escalates clients to 200, then `-s 20`,
   then flagship `-T 120`, or ships a written no-separation justification.
   No full sweep on an unjustified all-tie pilot.
3. Sweep: per cell, discarded `-T 30` warmup then measured `-T 60`
   (flagship `-T 120`), 3 repeats (5 flagship), median headline with
   min-max band and CV. Round-robin order (A,B,C,A,B,C...), never blocked.
   Per-cell caps (8 min standard, 12 flagship) enforced by the shared
   runner; over-cap is `timeout/inconclusive`, unsupported is
   `N/A (unsupported)` with null metrics, never zero.
4. Parse: `tps (without initial connection time)` from stdout; offline
   p50/p90/p99/p999 from per-transaction logs (`-l`, `time_us` column,
   filtered for skipped/failed/serialization markers); aggregate-interval
   logs for steady-state trimming. `failed > 1%` rejects the cell;
   SQLSTATE 26000 in a prepared twin fails that arm cell only.
5. Compare: headline deltas require non-overlapping min-max bands AND
   same-direction tps + p99 agreement; else `inconclusive`. Claims are
   comparative deltas inside the CI envelope only. Upgrades invalidate
   carried-forward numbers.
6. Chunk: sweep split into at least 4 job chunks (by workload pair), each
   with its own direct control, each under 60 min, resumable via manifest,
   artifacts committed as raw JSON plus medians.

## Module Breakdown

Harness language: **Python 3 (stdlib plus no new runtime deps)** driving
pgbench as a subprocess, with shell fixtures for pooler builds. Rejected
Go (extra toolchain for zero orchestration gain) and Rust (build friction
across five C/Elixir/Rust poolers buys nothing; rigor lives in fairness
discipline, not runner throughput). All procedure code is pooler-blind;
only `config_text()` and the connection port differ per arm.

```text
poolduel/
  harness/
    runner.py      shared procedure: init, checkpoint, warmup, measure,
                   log collect, caps, interleaving, manifest resume.
                   Owns timeouts; adapters never do. O(cells x arms x repeats)
                   spawns, O(1) state per cell.
    pgbench.py     argv builder per cell (identical flags per cell, only port
                   varies), stdout parser (tps line, header block, error
                   counts, exit codes), txn-log percentile math (file-size
                   proportional sort, sampling-rate guard at 200 MB).
    cells.py       M1 table (7 rows) + M2 axes as DATA, not code branches;
                   ratio guard (clients > 5x pool_size) rejects bad cells.
    stats.py       median/min/max/CV over at most 5 repeats (linear selection
                   or trivial sort); band-overlap + direction-agreement gate.
    schema.py      cell JSON validator (exact fields per harness-contract;
                   extra per-pooler fields forbidden; N/A rows carry nulls).
    chunk.py       workload-pair splitter, round-robin scheduler, resume
                   manifest, per-chunk direct-control injector.
    adapters/
      base.py      setup/start/healthcheck/stop/config_text interface.
      direct.py    control arm (no pooler, config_text records PG settings).
      pgagroal.py  pipeline + ev_backend + MAX_SIZE mapping; never auto.
      pgbouncer.py pool_mode + default_pool_size + max_prepared_statements
                   twin handling + N-instance so_reuseport launcher (M2).
      pgpool.py    session-class only; num_init_children x max_pool guard
                   (forbid 200x4 corner, substitute 200x1); N/A elsewhere.
      odyssey.py   pool + pool_size + workers; statement arm labeled
                   provisional pending empirical verify.
      pgcat.py     pool_mode + pool_size + worker_threads; statement is N/A.
  configs/       generated verbatim configs per cell (from docs baselines
                 plus grid values), each archived into its cell artifact.
  results/       raw per-cell JSON + medians JSON + stdout/txn/agg logs.
  site/
    index.html   static report (no build step): workload tables, best-vs-best
                 plus iso-region slices, delta-vs-control with bands,
                 N/A gray cells, inconclusive labels, threats-to-validity
                 section, version/SHA manifest. Served at /poolduel/.
  repro.sh       one-command local replay (same procedure code, smaller
                 default: pilot subset unless --full).
```

Adapter contract (normative, from `harness-contract.md`): identical
timeouts, warmup, invocation, failure semantics, and JSON schema for every
arm. Reviewer code-inspects for per-pooler special-casing; any adapter
warmup, retry, or timeout is a blocking finding.

CI workflow `.github/workflows/poolduel-m1.yml` (Builder authors, M1):
matrix of 4+ chunks following the postformer chunked pattern, same-runner
discipline, `ubuntu-24.04`, `-j` equals vCPU, pinned pooler builds
(pgagroal tip SHA recorded; PgBouncer tarball sha256 verified; release
tags elsewhere), per-chunk direct control, artifact upload + commit of
raw JSON plus medians. Nightly-only cells (`-R` capped, `-s 100`) are
never in the per-PR gate.

Pages: project report lives at `poolduel/site/` and publishes to
`/poolduel/index.html`; never root `/docs/` (global lab docs are
protected). No mock tables, no interpolated zeros, no placeholder charts:
every rendered number links to its raw JSON.

## Test Matrix

| Milestone | Cells | Gate |
|---|---|---|
| M1 pilot | M1-1 + M1-2, 1 repeat, all 6 arms interleaved | Separation (non-overlapping band on tps or p99 between 2+ arms) or escalate (200 clients, -s 20, -T 120) or written no-separation note |
| M1 sweep | M1-1..M1-7 per test-matrix (flagship 120s/5 reps on M1-1/M1-2; 60s/3 reps rest; churn twin M1-6 paired with M1-1; prepared twin M1-3 with 26000-fails-arm rule) | Tester reproduces >= 1 sample cell; anti-theater checklist (no home-team tuning, no sabotage by omission, no cherry-picked workloads, no hidden failures, no carried-forward numbers) |
| M2 modes | Session arms (M1-1/M1-2 workloads) + statement arms (PgBouncer yes; Odyssey provisional; rest N/A) | N/A published as N/A with nulls; Odyssey statement labeled provisional |
| M2 I/O | pgagroal io_uring vs epoll; PgBouncer 1 vs 2 so_reuseport; Odyssey workers {1,2,4}; pgcat worker_threads {1,5}; pgpool-II num_init_children/max_pool sweep | Equal measured-cell budget per pooler; realized counts published; imbalance fails review |
| M2 workloads | simple-update at M1-5 geometry for new arms; one churn twin; one prepared twin where supported | Same caps (8/12 min); timeout is inconclusive, never extrapolated |
| M3 report | Full M1+M2 medians, iso-region slices, surface-flatness notes, threats section, repro.sh green | Binding gate: Closes #302 only on matched-or-better comparative claims with bands; else Refs with negative ledger |

Budget parity: same total measured-cell count per pooler (M1: 7 workloads
x repeats; M2: at most 2 workloads per new arm). Iso-region rule: every
best-vs-best claim ships with at least one slice where clients, backends,
and duration match exactly.

## Risks and Non-Goals

- Co-located PG/pooler/pgbench on 2-4 vCPUs ranks arms on CI hardware
  only; documented, never generalized.
- pgpool-II blocking accept at 200 clients is a finding, not a harness
  bug; record and compare honestly.
- Out of scope: pgcat sharding/read-write split, Odyssey shared_pool,
  pgpool-II clustering beyond standalone, pipeline-mode pgbench,
  Supavisor (dedicated future milestone with metadata-DB fixture).
